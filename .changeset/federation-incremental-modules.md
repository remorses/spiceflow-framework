'spiceflow': patch

Fix federation "Module not found in remote registry" for streaming payloads and make module loading resilient. Streaming payloads (async generators) now announce client modules discovered mid-render via incremental `modules` SSE events, always emitted before the flight chunk that references them, so streamed JSX can mix server content with interactive client components (`encodeFederationPayload({ stream })` previously only supported server-rendered JSX). The client entry chunk is now identified by its exact filename from the assets manifest instead of an `index-*.js` regex, and modules whose code only lives in entry/framework chunks are announced with an empty chunk list plus a server-side error instead of being silently dropped. The consumer require patch now resolves host loader → remote registry → tagged error (host-first prevents same-site federation from shadowing the host's own modules with sync registry returns, which blanked pages on client navigation after a chat session decode) and memoizes per id so React's two-phase preload/require always sees the same promise instance. Failures are contained: a chunk that fails to load only breaks its own component, `RemoteIsland` wraps decoded trees in an error boundary that falls back to the static SSR HTML, and decode failures keep the SSR HTML instead of crashing the host page.
